1. Resume executif

AfriPay est presente publiquement comme une marketplace et une plateforme B2B unifiant le catalogue produit, les devis, la logistique et les paiements dans une experience integree. Le site public mentionne explicitement un environnement conçu pour "reprendre un panier, cadrer un devis, payer proprement et suivre la logistique sans zones floues".

La plateforme opere avec un site storefront public sur afripay.space et une API dediee sur api.afripay.space. Elle expose egalement un programme partenaire avec validation manuelle, dashboard privé, clés API, webhooks et documentation technique publique.

5. API partenaire AfriPay

La documentation publique d'AfriPay indique qu'un partenaire peut recuperer des produits, vendre sur son propre site, encaisser via AfriPay et automatiser les commandes et la livraison. La page /docs annonce explicitement un objectif d'integration rapide pour les developpeurs.

Fonction Endpoint / Mecanisme public documente Usage
Catalogue partenaire GET /api/partner/products Recuperer la liste des produits exploitables par un partenaire
Commande partenaire POST /api/partner/orders Creer une commande a partir d'un backend tiers
Documentation GET https://www.afripay.space/docs Consulter les guides, exemples curl, auth et webhooks
Source documentaire GET /api/docs Synchronisation de la page de documentation publique
Webhooks order.created, order.paid, order.shipped, order.delivered Synchronisation de statut et automatisation cote partenaire

Les cles partenaires restent dans l'espace dashboard et ne sont pas exposees publiquement. Cela demontre une separation claire entre la documentation publique et les secrets d'integration.

6. Securite et gouvernance d'acces

  • Aucun acces partenaire au dashboard n'est autorise sans validation manuelle prealable.
  • Le dashboard prive et ses routes sont masques avant approbation.
  • Les flux partenaires sont cloisonnes par compte approuve.
  • Le portail partenaire signe entre frontend et backend utilise une signature HMAC SHA-256.
  • La documentation publique impose un usage backend-only pour les secrets et l'authentification.
  • Les pratiques recommandees excluent l'exposition de APP_SECRET dans le frontend ou dans une application client publique.

7. Logistique et operations

  • AfriPay exploite un modele de sourcing avec devis, poids total, volume total et recommandation de mode de transport.
  • Le site storefront annonce des commandes compatibles expediees directement vers l'adresse client lorsque la destination est desservie.
  • Le systeme gere egalement des cas de reception interne et de dernier kilometre AfriPay selon le pays.
  • L'adresse logistique de reference visible dans le code fonctionnel est situee a Bron, Lyon, France.
  • Le footer met en avant "Timeline commande" et "Paiement tracable", indiquant une orientation operationnelle sur le suivi et la visibilite client.

8. Interet d'un acces API SHEIN pour AfriPay

  1. Etendre l'offre catalogue disponible sur une plateforme deja structuree pour le sourcing, le devis, la logistique et le paiement.
  2. Ajouter un nouveau fournisseur majeur dans un socle technique qui sait deja gerer catalogue, commandes, webhooks et operations.
  3. Permettre a AfriPay de proposer une experience multi-source plus large a ses partenaires e-commerce et a ses utilisateurs B2B.
  4. Beneficier d'un cadre de securite et de gouvernance deja en place pour les integrations partenaires et les acces API.
